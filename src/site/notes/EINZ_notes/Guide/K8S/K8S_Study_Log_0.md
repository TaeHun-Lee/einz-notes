# Kubernetes 객체(Kind) 종류와 기능

|**분류**|**Kind**|**기능**|
|---|---|---|
|**워크로드 (Workload)**<br><br>(파드 실행 및 관리)|**Pod**|쿠버네티스에서 컨테이너를 실행하는 가장 기본적이고 작은 단위임. 1개 이상의 컨테이너를 감싸고 있음.|
||**Deployment**|지정된 개수의 파드가 항상 실행되도록 유지하며, 애플리케이션의 버전 업데이트(무중단 배포)와 롤백을 관리함.|
||**StatefulSet**|데이터베이스처럼 데이터가 보존되어야 하고, 각 파드마다 고유한 이름(순서)이 필요한 상태 유지형 애플리케이션을 관리함.|
||**DaemonSet**|클러스터 내의 모든 서버(노드)마다 빠짐없이 파드를 1개씩 실행하도록 보장함. (로그 수집, 모니터링 에이전트 용도)|
||**Job / CronJob**|웹 서버처럼 계속 실행되는 것이 아니라, 특정 연산 등 일회성 작업을 수행하고 완료되면 파드를 종료함. (CronJob은 주기적 예약 실행)|
|**네트워크 (Network)**<br><br>(통신 및 트래픽 분산)|**Service**|파드가 재시작되어 IP가 변경되더라도, 외부 또는 내부에서 접근할 수 있는 고정된 IP와 도메인을 제공하고 트래픽을 분산(로드 밸런싱)함.|
||**Ingress**|단일 진입점으로 들어온 웹 트래픽(HTTP/HTTPS)을 URL 경로(예: `/api`, `/web`)나 도메인에 따라 알맞은 Service로 전달해 주는 라우터임.|
|**스토리지 (Storage)**<br><br>(데이터 영구 보존)|**PersistentVolume (PV)**|파드의 수명과 관계없이 데이터를 안전하게 보관하기 위해 클러스터에 세팅해 둔 실제 물리적 저장 공간임.|
||**PersistentVolumeClaim (PVC)**|파드가 스토리지를 사용하기 위해 필요한 용량(예: 1GB)과 읽기/쓰기 권한을 K8S에 요청하는 명세서임.|
|**설정 및 보안 (Config)**<br><br>(설정값 분리 주입)|**ConfigMap**|소스 코드를 수정하지 않고, 애플리케이션에 필요한 일반적인 설정값이나 환경 변수를 파드 외부에서 주입함.|
||**Secret**|데이터베이스 비밀번호, API 암호키 등 보안이 필요한 민감한 데이터를 인코딩하여 파드에 안전하게 주입함.|
|**확장성 (Scaling)**<br><br>(자동 스케일링)|**HorizontalPodAutoscaler (HPA)**|파드의 CPU나 메모리 사용량을 모니터링하여, 기준치 이상으로 부하가 발생하면 자동으로 파드 개수를 늘리고 부하가 적어지면 줄임.|

### 1. 추가적인 주요 기본(Built-in) Kind 목록

인프라를 더 정교하게 제어하기 위해 시스템 관리자 수준에서 다루는 객체들임.

- **보안 및 접근 제어 (RBAC)**
    - **`ServiceAccount`:** 파드(Pod)가 K8S API 시스템과 통신할 때 사용하는 '앱 전용 신분증'임.
    - **`Role` / `ClusterRole`:** "특정 파드를 삭제할 수 있다", "시크릿을 읽을 수 있다" 등의 '권한 규칙'임.
    - **`RoleBinding`:** 특정 ServiceAccount(신분증)에 Role(권한)을 부여하여 연결해 주는 서류임.

- **클러스터 구조 및 네트워크 제어**
    - **`Namespace`:** 하나의 거대한 K8S 클러스터를 개발용, 운영용 등 여러 개의 논리적 방으로 쪼개는 격리 공간임.
    - **`Node`:** K8S가 설치된 실제 물리 서버나 가상 머신 자체를 나타내는 객체임.
    - **`Endpoints` / `EndpointSlice`:** `Service`가 트래픽을 분산시킬 때 참고하는 '목적지 파드들의 실제 IP 주소 목록'임.
    - **`NetworkPolicy`:** 파드 간의 통신을 허용하거나 차단하는 내부 방화벽 규칙임.

- **스토리지 및 리소스 정책**
    - **`StorageClass`:** 앞서 실습에서 K8S가 자동으로 빈 폴더를 만들어주던 '동적 프로비저닝'을 설정하는 스토리지 템플릿임.
    - **`ResourceQuota` / `LimitRange`:** 파드 단위를 넘어, 특정 Namespace 전체가 쓸 수 있는 CPU/메모리 총량을 제한하는 정책임.

- **안정성 보장**
    - **`PodDisruptionBudget (PDB)`:** 서버 점검이나 장애 발생 시에도, 해당 앱의 파드가 '최소 몇 개 이상은 반드시 살아있어야 한다'고 강제하는 규칙임.

### 2. 커스텀 자원 (CRD)

가장 중요한 사실은 K8S의 `Kind` 개수는 고정되어 있지 않으며 **무한히 확장 가능**하다는 점임.

K8S는 **CRD(Custom Resource Definition)**라는 기능을 제공함. 이를 통해 사용자는 K8S 기본 메뉴얼에 없는 자신만의 완전히 새로운 `Kind`를 창조하여 K8S API에 등록할 수 있음.

- **예시:** 실무에서 많이 쓰는 외부 도구들을 K8S에 설치하면 다음과 같은 새로운 `Kind`들이 생성됨.
    - 깃옵스(GitOps) 도구인 **ArgoCD** 설치 ➡️ `Application` 이라는 Kind가 생김.
    - 모니터링 도구인 **Prometheus** 설치 ➡️ `ServiceMonitor` 라는 Kind가 생김.
    - 서비스 메시 도구인 **Istio** 설치 ➡️ `VirtualService`, `Gateway` 라는 Kind가 생김.
